# 0.0.8 "Coverage: SSH" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 0.0.8 — twelve SSH-backed tools: ZFS (status/datasets/snapshots/snapshot actions), GPU metrics, process list, disk spin, User Scripts (list/run), VM snapshots (list/create), and a deep SMART report.

**Architecture:** Every tool follows the `requireShell` pattern with a `command -v` availability probe returning a clear "not available on this server" error, `quoteForShell` on every interpolated value, `truncateOutput` on raw output, and the Phase 3 interactive gates where gated. New domain dirs: `src/tools/zfs/` (with a `_shared.ts` probe helper) and `src/tools/userscripts/`; disk tools join `src/tools/disk/`, GPU/process join `src/tools/system/`, VM snapshots join `src/tools/vm/`.

**Tech Stack:** as previous phases; no GraphQL — all `ShellExecutor`.

**Spec:** `docs/superpowers/specs/2026-09-14-competitive-roadmap-design.md` (Phase 5 section)

## Global Constraints

- Branch `feature/0.0.8-coverage-ssh` off `develop`; repo hard limits + quality gate as before.
- Spec command corrections are binding: ARC stats from `/proc/spl/kstat/zfs/arcstats` (no `arcstat` script on stock Unraid); array/pool disk spin via `emcmd cmdSpinup=diskN`/`cmdSpindown=diskN` (keeps emhttpd state consistent), `sdspin` only for unassigned `/dev/sdX`; User Scripts run by copying off the noexec flash (`tr -d '\r'`, run via `bash`); VM snapshots MUST be external (`virsh snapshot-create-as --atomic --disk-only`).
- **Descope (decision-log D12, pre-authorized by the spec):** VM snapshot revert/delete are dropped for this release; `vm_snapshot_list` + `vm_snapshot_create` ship. ZFS snapshot destroy/rollback ARE shipped (simple, well-defined CLI semantics, unlike libvirt external-snapshot chains).

## Tasks (each: failing tests → red → implement → green → registry entry + counts → gate → commit)

### Task 1: `src/tools/zfs/` — `zfs_status`, `zfs_dataset_list`, `zfs_snapshot_list`, `zfs_snapshot_action`
- `_shared.ts`: `probeZfs(shell): Promise<CallToolResult | null>` — `command -v zpool` (exit ≠ 0 → "ZFS is not available on this server (built into Unraid 6.12+; no pools may be configured)").
- `zfs_status`: `zpool list -H -o name,size,alloc,free,cap,health` parsed per pool; ARC line from `cat /proc/spl/kstat/zfs/arcstats` (parse `size` and `c_max` fields, report GiB + percent); concise = per-pool health line + ARC line. Read-only.
- `zfs_dataset_list`: `zfs list -H -p -o name,used,avail,refer,mountpoint` with optional `pool` filter (quoted); parsed rows; read-only.
- `zfs_snapshot_list`: `zfs list -H -t snapshot -o name,used,creation` with optional `dataset` filter (`-r` + quoted name); read-only.
- `zfs_snapshot_action` (tier-2): `create` → `zfs snapshot <dataset>@<name>`; `destroy` → `zfs destroy <dataset>@<name>` (target MUST contain `@` — validated so a bare dataset can never be destroyed); `rollback` → `zfs rollback <dataset>@<name>` (no `-r`: refuses non-latest with zfs's own error, surfaced verbatim). Snapshot name validated `^[A-Za-z0-9._:-]+$`; dataset `^[A-Za-z0-9._/:-]+$`.
- Commit: `feat(zfs): status, datasets, snapshots, and gated snapshot actions over SSH`.

### Task 2: `gpu_metrics` (`src/tools/system/gpu-metrics.ts`)
- Probe order: `command -v nvidia-smi` → full query (`--query-gpu=name,utilization.gpu,memory.used,memory.total,temperature.gpu,power.draw --format=csv,noheader,nounits`, parsed per GPU); else `command -v intel_gpu_top` → report detected + a bounded raw sample via `timeout 3 intel_gpu_top -J` (exit code from `timeout` tolerated), truncated; else clear "no GPU tooling found (nvidia/intel driver plugin not installed)". Read-only.
- Commit: `feat(system): gpu_metrics with nvidia/intel detection`.

### Task 3: `process_list` (`src/tools/system/process-list.ts`)
- `ps axo pid,pcpu,pmem,rss,etime,comm --sort=-<pcpu|pmem> | head -n <count+1>`; input `sort_by: cpu|memory` (default cpu), `count` (default 15, max 50, named constants); parsed rows; read-only.
- Commit: `feat(system): process_list top-N by cpu/memory`.

### Task 4: `disk_spin` (`src/tools/disk/disk-spin.ts`)
- Tier-1 confirm. Exactly one of `disk` (`^(disk[0-9]+|parity[0-9]?|cache[0-9]*)$` → `/usr/local/sbin/emcmd cmdSpinup=<disk>` / `cmdSpindown=<disk>`) or `device` (`^/dev/sd[a-z]+$` → `/usr/local/sbin/sdspin <device> up|down`, description noting ATA-only). NVMe rejected (doesn't spin).
- Commit: `feat(disk): gated disk_spin via emcmd/sdspin`.

### Task 5: `src/tools/userscripts/` — `user_script_list`, `user_script_run`
- `user_script_list`: `ls -1 /boot/config/plugins/user.scripts/scripts/ 2>/dev/null` — exit ≠ 0 or empty → "User Scripts plugin not installed (or no scripts)". Read-only.
- `user_script_run` (tier-2, description says arbitrary code by design): name validated `^[A-Za-z0-9 ._-]+$`; composed runner (flash is mounted noexec):
  `S=<quoted script path>; if [ ! -f "$S" ]; then echo "script not found"; exit 127; fi; T=$(mktemp); tr -d '\r' < "$S" > "$T"; bash "$T"; RC=$?; rm -f "$T"; exit $RC`
  `timeout_seconds` input (default 60, max 300). Output truncated both streams.
- Commit: `feat(userscripts): list and gated run replicating the plugin's noexec-safe runner`.

### Task 6: `vm_snapshot_list` + `vm_snapshot_create` (`src/tools/vm/`)
- Probe `command -v virsh`. `vm_snapshot_list`: `virsh snapshot-list <vm> --name` (quoted); empty → "no snapshots".
- `vm_snapshot_create` (tier-2): `virsh snapshot-create-as <vm> <name> --atomic --disk-only` — external disk snapshots matching Unraid 7's own flow (internal snapshots fail on raw disks and are refused for OVMF VMs). Name validated `^[A-Za-z0-9._-]+$`. Description states revert/delete are deliberately not offered yet (chain-corruption risk) and points at the Unraid UI.
- Commit: `feat(vm): external snapshot list/create via virsh`.

### Task 7: `disk_smart_report` (`src/tools/disk/disk-smart-report.ts`)
- Probe `command -v smartctl`; `smartctl -a <device>` for `^/dev/(sd[a-z]+|nvme[0-9]+n[0-9]+)$`; smartctl's non-zero informational exit codes (bitmask) are tolerated — output is returned whenever present; truncated. Read-only.
- Commit: `feat(disk): deep SMART report via smartctl`.

### Task 8: Docs + release prep
- README: "ZFS", "User Scripts" sections + rows for gpu_metrics/process_list/disk_spin/vm snapshots/smart report in existing sections; decision log D12; registry counts 46→58 (read-only 25→33); drift check; gate; push; draft PR.

**Acceptance:** all tools degrade cleanly without SSH and on missing binaries (tested via fakes); quoting uses `quoteForShell` everywhere; 0.0.8 on npm.
