# 0.0.6 "Modern MCP" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 0.0.6 — elicitation-backed confirmation gates with argument fallback, MCP resources (`unraid://schema|health|doctor`), guided prompts, a complete annotations audit (`idempotentHint` everywhere), and `outputSchema`/`structuredContent` on the four structured read tools.

**Architecture:** A new `ElicitationChannel` seam (built once per server from `McpServer.server.getClientCapabilities()` + `elicitInput`) is threaded into every gated tool's handler factory as an optional trailing parameter; the two gate helpers in `_shared/confirm.ts` gain async interactive variants that fall back to today's argument-refusal copy byte-for-byte when the channel is absent or the client lacks the capability. Resources and prompts live in new `src/resources/` and `src/prompts/` directories, reusing extracted `runSystemHealth`/`runConnectionDoctor` cores. The annotations audit is enforced by a registry test iterating `TOOL_REGISTRATIONS`.

**Tech Stack:** @modelcontextprotocol/sdk 1.29 (`elicitInput` with `ElicitRequestFormParams`, `registerResource`, `registerPrompt`, `outputSchema`/`structuredContent`), zod v3, vitest.

**Spec:** `docs/superpowers/specs/2026-09-14-competitive-roadmap-design.md` (Phase 3 section)

## Global Constraints

- Branch `feature/0.0.6-modern-mcp` off `develop`; repo hard limits and quality gate as in previous phases.
- Elicitation request timeout: named `ELICITATION_TIMEOUT_MS = 300_000` (humans read slowly; SDK default is 60 s).
- Existing refusal copy must stay byte-identical on the fallback path (existing tests assert it).
- Elicitation only works over stdio/session-HTTP; on stateless HTTP `getClientCapabilities()` is per-request and the helper must degrade to the argument path without erroring.

### Task 1: `ElicitationChannel` + async interactive gates

**Files:**
- Create: `src/tools/_shared/elicitation.ts` + `elicitation.test.ts`
- Modify: `src/tools/_shared/confirm.ts` + `confirm.test.ts`

**Interfaces (produced):**
- `interface ElicitationChannel { isAvailable(): boolean; confirm(request: ElicitationPrompt): Promise<ElicitationOutcome> }` with
  `interface ElicitationPrompt { message: string; requireRiskAcknowledgement: boolean }` and
  `type ElicitationOutcome = "accepted" | "declined" | "unavailable"`.
- `createElicitationChannel(server: McpServer): ElicitationChannel` — real impl: `isAvailable()` = `server.server.getClientCapabilities()?.elicitation !== undefined`; `confirm` calls `server.server.elicitInput({ message, requestedSchema: { type: "object", properties: { confirm: { type: "boolean", title, description } , (acknowledge_risk when tier-2) }, required: [...] } }, { timeout: ELICITATION_TIMEOUT_MS })`; maps `action === "accept"` && all requested booleans true → "accepted"; accept-with-false / "decline" / "cancel" → "declined"; thrown errors → "unavailable" (fall back to args, never crash the tool).
- `confirm.ts` gains async gates (the sync ones remain for internal reuse):
  - `requireConfirmationInteractive(options: { confirm?: boolean; actionDescription: string; channel?: ElicitationChannel | null }): Promise<CallToolResult | null>`
  - `requireRiskAcknowledgementInteractive(options: { flags: RiskGateFlags; refusalMessage: string; channel?: ElicitationChannel | null }): Promise<CallToolResult | null>`
  - Logic, both: explicit args satisfied → `null`. Else if `channel?.isAvailable()` → `channel.confirm(...)`: "accepted" → `null`; "declined" → `toolError` naming the human decline ("The user declined the confirmation prompt. No changes were made."); "unavailable" → fall through. Fallback → the existing sync gate's refusal (byte-identical copy).
- Tests: channel fake with scripted outcomes; each gate × {args satisfied, accepted, declined, unavailable→fallback copy, no channel→fallback copy}; real-channel unit tests with a fake `server.server` object (capabilities present/absent, elicitInput accept-true/accept-false/decline/throw; assert the passed timeout equals 300000 and required booleans are in `requestedSchema.required`).

- [ ] TDD steps, then commit `feat(mcp): elicitation channel and interactive confirmation gates`.

### Task 2: Migrate all 14 gated tools

**Files:** every file listed by `grep -l "requireConfirmation\|requireRiskAcknowledgement" src/tools --include="*.ts" | grep -v test | grep -v _shared` (14 tools), plus `src/tools/registry.ts` is untouched (register functions already receive `server`).

**Change per tool (mechanical):**
1. Handler factory gains optional trailing `channel?: ElicitationChannel | null` parameter (stays ≤ 3 params — fold into an options object only where it would exceed).
2. The sync gate call becomes `await` of the interactive variant with `channel`.
3. `registerX(...)` passes `createElicitationChannel(server)` when constructing the handler.
- Existing tests pass unchanged (no channel → fallback). Add elicitation-path tests to TWO representative tools: `docker_container_action` (tier-1: accepted runs the mutation; declined runs nothing) and `system_power` (tier-2: accepted issues the command; declined issues nothing).

- [ ] Migrate + tests → gate → commit `feat(tools): interactive elicitation gates across all gated tools`.

### Task 3: Resources

**Files:**
- Create: `src/resources/registry.ts` (+ `registry.test.ts`), `src/resources/schema-sdl.ts` (+ test)
- Modify: `src/tools/system/system-health.ts` (export `runSystemHealth(client): Promise<HealthReport>` — the existing handler body's compute; handler reuses it), `src/tools/system/connection-doctor.ts` (export `runConnectionDoctor(deps): Promise<{ checks: DoctorCheck[] }>`), `src/server.ts` (call `registerAllResources(server, options)`)

**Interfaces:**
- `registerAllResources(server: McpServer, options: RegistryOptions): void` registers:
  - `unraid-schema` @ `unraid://schema` (mimeType `application/graphql`) → SDL text via `loadSchemaSdl()`
  - `unraid-health` @ `unraid://health` (mimeType `application/json`) → `JSON.stringify(await runSystemHealth(client))`
  - `unraid-doctor` @ `unraid://doctor` (mimeType `application/json`) → `JSON.stringify(await runConnectionDoctor(options))`
- `loadSchemaSdl(readFile?: (path: URL) => string): string` — tries `../schema/unraid.graphql` then `../../schema/unraid.graphql` relative to `import.meta.url` (dist build vs src execution); throws a descriptive error if neither exists.
- Tests: fake McpServer recording `registerResource` calls; read callbacks return `contents[0].text` with the right uri/mimeType; health/doctor callbacks tested with recording executors; error inside a read callback surfaces as a thrown error (SDK turns it into a resource error).

- [ ] TDD → commit `feat(mcp): unraid://schema, unraid://health, unraid://doctor resources`.

### Task 4: Prompts

**Files:** Create `src/prompts/registry.ts` + `registry.test.ts`; modify `src/server.ts` (call `registerAllPrompts(server)`).

**Interfaces:** `registerAllPrompts(server: McpServer): void` registers four prompts via `server.registerPrompt(name, { title, description, argsSchema? }, callback)`:
- `triage-array-problem` (no args) — walks system_health → array_status → disk_list → notification_alerts → parity_history, ending with gated-fix guidance.
- `find-resource-hog` (no args) — system_metrics → docker_stats → process-level guidance via shell_exec, comparing container CPU/memory.
- `safe-container-update` (arg: `container` optional) — docker_container_list (update availability) → backup note → docker_container_update → post-check logs.
- `health-report` (no args) — system_health detailed + ups_status + parity_history into a formatted owner-readable report.
Each callback returns `{ messages: [{ role: "user", content: { type: "text", text: <full workflow text> } }] }`.
- Tests: fake server records registrations; each callback's text mentions the tools it orchestrates; count = 4.

- [ ] TDD → commit `feat(mcp): guided workflow prompts`.

### Task 5: Annotations audit — `idempotentHint` everywhere

**Files:** every tool file's `annotations` object (41 tools); `src/tools/registry.test.ts`.

- Reads get `idempotentHint: true`. Mutations: `true` only for same-state-settling operations (`docker_autostart_set`, `notification_archive`, `notification_recalculate`); all other mutations `false` (actions/creates/deletes either error or act again on repeat).
- Registry test: for every entry in `TOOL_REGISTRATIONS`, register in isolation and assert the annotations object has explicit boolean `readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint`.

- [ ] Failing registry test → mechanical edits → commit `feat(tools): complete annotation audit with idempotentHint`.

### Task 6: `outputSchema` + `structuredContent` for the four structured reads

**Files:**
- Modify: `src/tools/_shared/respond.ts` (+ test): `formatStructuredResponse(format: ResponseFormat, concise: string, structured: Record<string, unknown>): CallToolResult` — always sets `structuredContent: structured`; text block = concise summary in concise mode, pretty JSON (truncation-enveloped) in detailed mode.
- Modify: `system-health.ts`, `system-metrics.ts`, `array-status.ts`, `container-list.ts`: add `outputSchema` (permissive zod raw shape naming the top-level fields, e.g. health: `{ overall: z.enum(["ok","warning","critical"]), subsystems: z.array(z.object({ subsystem: z.string(), severity: z.string(), detail: z.string() })) }`; metrics/array/containers: top-level keys with `z.unknown()` values where deep typing adds no safety) and switch handlers to `formatStructuredResponse`. Container list's structured payload is `{ containers, data_age_ms }` (objects, not bare arrays — structuredContent must be an object).
- Tests per tool: result carries `structuredContent` in BOTH modes; concise text is the summary; registry test spot-checks `outputSchema` present on the four.

- [ ] TDD → commit `feat(mcp): structured output for health, metrics, array, and container list`.
