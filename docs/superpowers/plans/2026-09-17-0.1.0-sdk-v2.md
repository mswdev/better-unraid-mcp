# 0.1.0 "SDK v2 + zod v4 migration" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 0.1.0 — the server on the MCP TypeScript SDK v2 packages (protocol 2026-07-28) and zod 4, with provably unchanged behavior (the full test suite passes with only mechanical assertion edits), every behavioral delta decision-logged.

**Architecture:** Replace the monolithic `@modelcontextprotocol/sdk@1.x` with `@modelcontextprotocol/server@2` (McpServer, `CallToolResult`, `ResourceTemplate`, stdio transport under `/stdio`) and `@modelcontextprotocol/node@2` (`NodeStreamableHTTPServerTransport`, same option names as v1: `sessionIdGenerator`, `enableJsonResponse`, `allowedHosts`, `enableDnsRebindingProtection`); zod `^4.2` (4.6.5 verified available) everywhere. Registration keeps `registerTool`/`registerResource`/`registerPrompt` but wraps raw shapes in `z.object()` (v2 deprecates raw shapes); low-level `setRequestHandler(Schema, …)` becomes method strings; handler `extra` becomes `ctx` (`ctx.mcpReq._meta.progressToken`, `ctx.mcpReq.notify(...)`). Node floor stays `>=20` (v2 requires exactly that), so `ws` stays and `engines` is unchanged.

**Tech Stack:** `@modelcontextprotocol/server@^2.0.0`, `@modelcontextprotocol/node@^2.0.0`, `zod@^4.2.0`; the official codemod `@modelcontextprotocol/codemod` for the mechanical pass.

**Spec:** `docs/superpowers/specs/2026-09-15-roadmap-2-design.md` §6 Phase 5.

## Verified facts (2026-09-17, from the published packages and `docs/migration/upgrade-to-v2.md`)

- Published: `@modelcontextprotocol/{server,client,core,node}@2.0.0`; `engines.node >=20`; `zod ^4.2.0` dependency. `@modelcontextprotocol/sdk` latest 1.30.0 (we are on ^1.29).
- `McpServer` keeps: `registerTool` (raw `ZodRawShape` overload `@deprecated` but present; Standard Schema objects preferred), `registerResource(name, uriOrTemplate, metadata, reader)`, `registerPrompt`, `.server` accessor (`registerCapabilities`, `setRequestHandler(methodString, handler)`, `sendResourceUpdated`, `elicitInput`, `getClientCapabilities` (deprecated but functional), `onclose`), `connect`, `close`.
- `setRequestHandler('resources/subscribe', async (request, ctx) => …)` — spec-method form receives the full request envelope.
- Handler context: `ctx.mcpReq.{id,_meta,signal,notify,send,elicitInput}`; `ctx.sessionId`; `ctx.http?.req` (Web `Request`).
- Elicitation form params unchanged in shape: `{ message, requestedSchema: { type: "object", properties, required? } }` (`mode: "form"` optional).
- Transports: `import { StdioServerTransport } from "@modelcontextprotocol/server/stdio"`; `import { NodeStreamableHTTPServerTransport } from "@modelcontextprotocol/node"`; `handleRequest(req, res, parsedBody?)` unchanged.
- Behavior changes to expect: `McpServer` advertises `listChanged: true` for declared primitives; stdio read buffer capped at 10 MB and non-JSON stdout lines skipped; POST without `Content-Type: application/json` → 415.
- zod 4: `z.record(k, v)` needs both args; `z.ZodIssueCode.custom` → `code: "custom"`; `superRefine` still exists; `.default()`/`.optional()`/`z.enum` unchanged for our usage.

## Global Constraints

- Branch `feature/0.1.0-sdk-v2` off `develop`; draft PR into `develop`; gate before every commit; `npm run format` after `npm version`.
- `.claude/rules/` hard limits apply to every touched function (the codemod does not reflow; re-check 25-line caps where it wraps shapes).
- Behavior contract = the existing test suite: assertion edits allowed only where the SDK changed a wire detail (documented in D34); no test deleted.
- The scratchpad acceptance harness (SDK 1.x client) must still complete the read/subscribe run against the local build — a v1 client talking to the v2 server proves version negotiation.
