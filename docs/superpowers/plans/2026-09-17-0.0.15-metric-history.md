# 0.0.15 "Metric history" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 0.0.15 — an opt-in in-memory metrics recorder (`MCP_METRICS_HISTORY=true`) that keeps 24 h of 30-second min/avg/max buckets for CPU, memory, and network from the graphql-ws feed, exposed through a read-only `metrics_history` tool and a mirroring `unraid://live/history` resource, both of which explain exactly how to enable recording when it is off.

**Architecture:** `src/graphql/metric-subscriptions.ts` holds the three subscription specs (shared with `live-resources.ts`, which stops inlining them). `src/graphql/metrics-history.ts` adds `MetricRingBuffer` (fixed 2880-slot ring keyed by bucket index, per-series min/sum/max/count) and `MetricsHistoryRecorder` (subscribes the three feeds on `start()`, extracts scalar series per sample, folds into buffers, `dispose()` unsubscribes). `src/tools/metrics/metrics-history.ts` renders a window; `src/resources/history-resource.ts` renders every topic's last hour. `src/index.ts` builds the recorder only when the env flag is on and passes it via `RegistryOptions.history`.

**Tech Stack:** unchanged (graphql-ws feed already present).

**Spec:** `docs/superpowers/specs/2026-09-15-roadmap-2-design.md` §6 Phase 4.

## Global Constraints

- Branch `feature/0.0.15-metric-history` off `develop` (after 0.0.14 merged); draft PR into `develop`; gate before every commit; `npm run format` after `npm version`.
- Named constants: `BUCKET_MS = 30_000`, `RETENTION_MS = 24 * 60 * 60 * 1000`, `BUCKET_CAPACITY = RETENTION_MS / BUCKET_MS` (2880), `DEFAULT_WINDOW_MINUTES = 60`, `MAX_WINDOW_MINUTES = 1440`, `CONCISE_ROWS = 24`.
- Memory-bounded and process-lifetime only (no disk persistence) — documented honestly in the tool, resource, README, and `.env.example`.
- Gaps are honest: buckets with no sample are simply absent from the output and counted in a `gaps` field.
- `src/tools/system/` stays at 9 files — the tool lives in a new `src/tools/metrics/` directory.

### Task 1: Ring buffer + recorder (`src/graphql/metric-subscriptions.ts`, `src/graphql/metrics-history.ts` + tests)

**Interfaces:**
```ts
// metric-subscriptions.ts
export type MetricTopic = "cpu" | "memory" | "network";
export interface MetricSubscription { topic: MetricTopic; feedTopic: string; query: string }
export const METRIC_SUBSCRIPTIONS: Record<MetricTopic, MetricSubscription>; // feedTopic: systemMetricsCpu / systemMetricsMemory / systemMetricsNetwork; queries copied verbatim from live-resources
/** Scalar series extracted from one feed sample; null when the sample has no usable numbers. */
export function extractSeries(topic: MetricTopic, sample: unknown): Record<string, number> | null;
//   cpu → { percent: systemMetricsCpu.percentTotal }
//   memory → { percent: systemMetricsMemory.percentTotal, usedBytes: used }
//   network → { rxBytesPerSec: Σ rxSec, txBytesPerSec: Σ txSec } over interfaces except "lo"

// metrics-history.ts
export const BUCKET_MS = 30_000; export const RETENTION_MS = 86_400_000; export const BUCKET_CAPACITY = 2_880;
export interface SeriesStats { min: number; max: number; avg: number; count: number }
export interface HistoryPoint { bucketStartMs: number; series: Record<string, SeriesStats> }
export class MetricRingBuffer { constructor(now?: () => number); add(values: Record<string, number>, atMs?: number): void; window(sinceMs: number): HistoryPoint[]; size(): number }
export interface RecorderDeps { feed: Pick<SubscriptionFeed, "subscribe">; now?: () => number }
export class MetricsHistoryRecorder { constructor(deps: RecorderDeps); start(): void; dispose(): void; isRunning(): boolean; window(topic: MetricTopic, windowMinutes: number): { points: HistoryPoint[]; gaps: number; expectedBuckets: number }; startedAtMs(): number | null }
```
Tests (`metrics-history.test.ts`, injected clock): two samples in one bucket fold to min/max/avg/count 2; samples 30 s apart make two points; a slot is overwritten after 24 h (add at t, add at t+RETENTION → window returns only the newer); `window` excludes buckets older than `since`; `gaps` = expected − present; recorder subscribes exactly the three feed topics on `start()` and never before; a pumped cpu sample lands in the cpu buffer; unparsable samples are ignored; `dispose()` calls every unsubscribe and `isRunning()` false. `metric-subscriptions.test.ts`: `extractSeries` per topic incl. `lo` exclusion and null for garbage. `live-resources.test.ts` keeps passing (metrics entry now built from `METRIC_SUBSCRIPTIONS`).

### Task 2: `metrics_history` tool (`src/tools/metrics/metrics-history.ts` + test) and registry option

- `RegistryOptions.history?: MetricsHistoryRecorder | null`.
- Input: `topic: z.enum(["cpu","memory","network"])`, `window_minutes: z.number().int().positive().max(MAX_WINDOW_MINUTES).default(DEFAULT_WINDOW_MINUTES)`, `response_format`.
- Off (`history` null): non-error text `Metric history is off. Start the server with MCP_METRICS_HISTORY=true to record CPU, memory, and network at 30-second resolution for 24 hours (in memory only; cleared on restart).`
- On but empty: `Recording since <ISO>; no <topic> samples yet (the WebSocket feed delivers the first sample within a few seconds).`
- Concise: header line `cpu — last 60 min: N points, G gaps (30 s buckets)` then a compact table of ≤ `CONCISE_ROWS` rows, each row aggregating consecutive buckets (`HH:MM  min/avg/max` per series, 1 decimal). Detailed: `{ topic, window_minutes, bucket_ms, points: [{ time, series }], gaps, recording_since }` (times ISO).
- Tests: off message; empty message; renders points with min/avg/max; concise never exceeds 24 rows for a 24 h window; clamps to the recorder window; detailed JSON shape.

### Task 3: `unraid://live/history` resource (`src/resources/history-resource.ts` + test) and env/index wiring

- `registerHistoryResource(server, history | null)`: JSON `{ enabled: false, hint: "<same enable text>" }` or `{ enabled: true, window_minutes: 60, bucket_ms: 30000, recording_since, topics: { cpu: {points, gaps}, memory: …, network: … } }`.
