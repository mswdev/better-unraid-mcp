# 0.0.5 "Fast" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 0.0.5 — persistent SSH, hardened GraphQL client (timeout, keep-alive agent, query-only retry), a TTL snapshot cache for hot reads, MCP progress notifications, and an opt-in stateful HTTP session mode.

**Architecture:** The `ShellExecutor` interface is untouched — `SshShellExecutor` internally becomes a lazily-connected, kept-alive, auto-reconnecting connection manager with a bounded channel semaphore, testable through an injected connection factory. GraphQL hardening lands in `execute.ts` (timeout + shared keep-alive undici agent) and `client.ts` (jittered retry for query operations only). The snapshot cache is a `GraphQLExecutor` decorator caching a fixed allow-list of hot documents; tools read serve-age through a WeakMap helper. Progress notifications use the SDK's `RequestHandlerExtra` second handler argument. Session mode adds a session map to the HTTP transport behind `MCP_HTTP_SESSIONS=true`.

**Tech Stack:** TypeScript (ESM), @modelcontextprotocol/sdk 1.x, ssh2, undici, zod v3, vitest.

**Spec:** `docs/superpowers/specs/2026-09-14-competitive-roadmap-design.md` (Phase 2 section)

## Global Constraints

- Branch `feature/0.0.5-fast` off `develop`.
- Hard limits: methods ≤ 25 lines, nesting ≤ 2, ≤ 3 params, no magic numbers, JSDoc on all exports, early returns.
- Hand-written fakes only; Arrange-Act-Assert; quality gate (`npm run typecheck && npm run build && npm test && npm run lint`) before every commit.
- Never hand-edit `schema/unraid.graphql` or `src/types/unraid/**`.
- Named defaults from the spec: SSH idle disconnect 90 s (`UNRAID_SSH_IDLE_SECONDS`), GraphQL request timeout 30 s, snapshot-cache TTL ~5 s.

**Interfaces:**
- Produces: `SshSettings` gains `idleSeconds?: number`. New exported seam for tests:
  `interface SshConnection { exec(command: string): Promise<ShellResult>; end(): void; onClose(listener: () => void): void }` and
  `type SshConnectionFactory = (config: ConnectConfig) => Promise<SshConnection>`;
  `SshShellExecutor` constructor takes `(settings: SshSettings, connectionFactory?: SshConnectionFactory)` (default = real ssh2 factory with `keepaliveInterval`).
- Behavior contract (each bullet is a test):
  1. First `execute` connects; a second `execute` reuses the same connection (factory called once).
  2. After the connection reports close, the next `execute` reconnects (factory called again).
  3. After `idleSeconds` with no calls (fake timer via injectable `setTimerFn`/`clearTimerFn` or vitest fake timers), the connection is ended.
  4. At most `MAX_CONCURRENT_CHANNELS` (named constant, 4) `exec`s run concurrently; a 5th waits until one finishes.
  5. A factory rejection surfaces as a clean error and the next call retries the connect (no wedged state).
  6. Per-call `timeoutMs` still applies to connect + exec (reuse `withTimeout`).
- Real factory: `client.connect({...config, keepaliveInterval: KEEPALIVE_INTERVAL_MS (15_000), keepaliveCountMax: KEEPALIVE_COUNT_MAX (3)})`; `onClose` binds both `close` and `error` events; `exec` wraps the existing `run`/`collect` helpers.

- [ ] Steps: failing tests for the six behaviors → red → implement → green → env plumbing (`UNRAID_SSH_IDLE_SECONDS` test: default 90, custom parse) → full gate → commit `feat(ssh): persistent kept-alive SSH connection with idle disconnect`.

### Task 3: Query-only jittered retry

**Files:**
- Modify: `src/graphql/client.ts` + `src/graphql/client.test.ts`

**Interfaces:**
- Produces: constants `MAX_QUERY_RETRIES = 2`, `RETRY_BASE_DELAY_MS = 250`. Helper `isQueryOperation(document): boolean` (first operation definition's `operation === "query"`). Retry applies to network-level failures (`HttpStatusError` with status ≥ 500, or fetch/timeout `Error`s that are not `UnraidApiError`) — never to GraphQL-level errors, never to mutations. Jitter: `delay = RETRY_BASE_DELAY_MS * 2^attempt * (0.5 + random())` behind injectable `random` (config field, default `Math.random`). The existing single 429 retry stays and is unified into the same retry loop (429 counts for both queries and mutations — safe: the request was never admitted).
- Tests: query retried on 500 then succeeds (fetch called twice); mutation NOT retried on 500 (fetch called once); query not retried on `UnraidApiError` (GraphQL errors); retries bounded (3 total attempts on persistent 500 then throws).

- [ ] Steps: failing tests → red → implement (keep `execute` ≤ 25 lines by extracting `executeWithRetry`) → green → gate → commit `feat(graphql): bounded jittered retry for idempotent queries`.

- `docker_container_update`: emits `sendProgress` before the mutation (progress 0, message naming the target) and after (progress 1, total 1). Tests assert both notifications with a recorded fake; and that a missing token sends nothing.

NO — the `SessionStore` is created in `startHttp` and passed via options (`sessionStore?: SessionStore`), keeping `routeRequest` pure. Stateless behavior unchanged when the flag is off (default).
- Tests: initialize request creates a session (size 1); request with unknown session id → 404 with "Session not found"; DELETE removes (size 0); sweep expires idle sessions (fake `now`); non-session mode untouched (existing tests still pass). Use fake transports by injecting `buildServer: () => fake` — the store's transport creation is behind an injectable `buildTransport` option field for tests (`buildTransport?: (onInit: (id: string) => void) => TransportLike` where `TransportLike = { handleRequest(req, res, body): Promise<void>; close(): Promise<void>; sessionId?: string }`).
