> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 0.0.11 — the "validated on real hardware" release — fixing every FAIL from the 2026-09-17 acceptance run against Deepwater (Unraid 7.3.2, API 4.37.4) and recording the upstream quirks discovered.

**Architecture:** Four surgical tool fixes, each behind the existing executor/shell seams: `system_health` (and the `unraid://health` resource, which reuses `runSystemHealth`) reads UPS data in a SEPARATE query so an apcaccess failure degrades to an honest "ups: unavailable" line instead of failing the whole rollup; `ups_status` turns the known upstream `No UPS data returned from apcaccess` error into a non-error "no live UPS data" report (NUT-managed UPSes are invisible to the Unraid API); `disk_list` filters the upstream partition-prefix bleed (`/dev/sda` listing `sdaa1…sdae1`); `gpu_metrics` parses `intel_gpu_top -J` into a one-line summary instead of dumping raw JSON. Plus the acceptance report, decision log, memory notes, status table, version bump.

**Tech Stack:** unchanged (TypeScript, zod 3, vitest, graphql-codegen for the `.graphql` documents).

**Spec:** `docs/superpowers/specs/2026-09-15-roadmap-2-design.md` §6 Phase 0.

```ts
type Partition = DiskListQuery["disks"][number]["partitions"][number];

/** Partition names are `<device>` + optional `p` + digits (sda1, nvme0n1p1). */
const PARTITION_SUFFIX_PATTERN = "p?[0-9]+$";

/**
 * Keeps only partitions that really belong to `device`. The Unraid API matches
 * partitions by name prefix, so `/dev/sda` also lists `sdaa1`, `sdab1`, …
 * on servers with more than 26 disks (observed on Unraid 7.3.2 / API 4.37.4).
 */
export function partitionsOfDevice(device: string, partitions: Partition[]): Partition[] {
  const base = device.replace(/^\/dev\//, "");
  const pattern = new RegExp(`^${base}${PARTITION_SUFFIX_PATTERN}`);
  return partitions.filter((partition) => pattern.test(partition.name));
}
```

Apply it in the handler: `const disks = data.disks.map((disk) => ({ ...disk, partitions: partitionsOfDevice(disk.device, disk.partitions) }));` and pass `disks` to `summarize`/`formatResponse`. Note: `base` contains no regex metacharacters for `/dev/sdX` and `/dev/nvmeXnY`; escape defensively with `base.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")` in a small `escapeRegExp` helper.
